# doda · 聊着把想法做出来

[下载 Windows 安装包或 Mac 通用包](https://github.com/DCM-dc/doda/releases/latest)。发布包内置运行环境、预览截图引擎和本机语音识别模型，首次使用在设置中填写自己的 DeepSeek、MiMo key。Windows 安装后从开始菜单打开；Mac 将 doda 拖入 Applications。详细安装说明与验证范围见 [RELEASE_NOTES.md](./RELEASE_NOTES.md)。

doda 的主线是持续聊天。先聊具体功能和规则，再聊视觉感觉；不展示设计风格选择器。需求摘要直接留在对话里，确认后由独立 DSH 进程生成微信原生小程序，用户全程与 doda 协作。制作期间仍能继续聊，下一轮想法不会改动正在执行的需求快照。交付后，主对话能依据最近成功版本的实际内容接着聊作品。

右侧只保留预览。iPhone 15 Pro、iPhone 13、iPhone SE、Pixel 9 使用各自的屏幕尺寸、安全区域、灵动岛、刘海或挖孔和手机边框；切换机型保留正在体验的页面状态。微信胶囊菜单可以重新打开作品，底部导航只按工程自身的 `app.json` 渲染。预览工具栏提供刷新、页面切换、工程检查、开发者工具和源码 ZIP。

回复中的强调、段落与列表正常呈现，朗读提取其中的文字，保留代码和转义符号的含义。用户原话与历史记录保留原始文本。使用 CommonMark，不执行原始 HTML；图片语法只显示描述，不加载远程图片。

## 本机使用

当前服务地址：http://127.0.0.1:4318/ 。点圆形小球开始语音，说完停顿约一秒自动发送，回复播完继续听。播报时可点“我想说一句”打断，也可以切换“打字聊”。

连续说长句时，每约 25 秒先识别一段，麦克风继续收听；实际停顿后合并整句话，只发送一轮聊天。没有语音的结束片段只结束本轮，不送去识别；全零 PCM 录音返回空文本。停止后旧录音不会混入新会话。

窄窗口可用侧栏菜单展开作品名称，点击外面或按 Escape 收起。点回当前作品只收起列表，保留未发送的聊天和当前预览；切换到另一个作品仍会重置本地编辑状态。

普通保存成功提示在五秒后收起；错误、编译警告和详细输出保留到手动关闭。实际页面五次独立加载验证自动关闭，并验证连续保存延长新提示时间、成功计时器不会关掉后来的错误。

等待文字回复时仍可写下一句。迟到的回复归回原作品，不清空另一件作品的输入；在同一件作品新写、改回相同文字或切走再回来，也保留新草稿。新点子从空白输入开始，欢迎页的起始想法仍会带入。跨作品场景经过五次真实 DeepSeek 页面回归，另有四类输入边界及故意移除保护后的变红验证。

生成期间，普通模式空闲 25 秒、活泼模式空闲 12 秒后，doda 会围绕已确认的点子接一个容易回答的问题，每轮生成最多一次。安静模式、正在说话、任务结束和收官后都不会主动插话。问句先生成，确认麦克风空闲和上下文仍有效后才进入聊天；已开始播报的短句不会被完成提醒截断；不伪造用户消息，也不修改需求卡。当前按句往返，尚未实现自动抢话。

说“今天聊到这里”“晚安”或明确要求结束语音时，最后一句回复播完后退出聆听；作品完成与继续聊天分别处理。引用、假设、否定结束或“作品完成但继续聊”不会据此关闭语音。明确结束语音也不要求结束文字聊天。

同一句话里改主意时，以后面的明确决定为准：先想继续聊、后来道别会退出，先要结束、后来继续语音会继续听。转成打字仍关闭语音；识别结果漏掉“结束语音之后打字继续聊”中间的逗号，也能处理。五组三种实际录音对话通过，保持需求与执行记录不变；这仍是有限句式识别。

语音纠正需求后，说“更新这张卡给我看”会展示当前卡片并更新待确认版本；下一句确认交付这一版。查看卡片不会开始编程，引用或否定查看请求也不插入确认。重复纠正可能重新组织相同验收文案并增加版本，确认始终对应实际最新的卡片。

已经成功交付、没有编程任务或需求错误时，说“作品完成了，我们继续聊”会让作品收官，同时保留文字和语音入口。继续讨论时不改需求卡或启动新任务；未交付、“还没完成”、引用完成文字、假设或提问都不触发这条收官识别。五个真实 DeepSeek 对话项目、五个独立录音语音会话和五个真实界面项目验证通过；男、女预设录音都在收官后继续聆听，只在道别回复播完后退出。原颜色小册的十二条记录仍可回看。

明确说“继续随便聊，不整理、不改作品”时，doda 继续接感受和生活联想，保留需求、版本和执行记录，不把否定的“整理”误当成整理请求。用户未询问的代码与实现附录会触发一次真实模型重写；仍有附录时，只保留能够独立成立的相关首段，否则保留输入并提示重试。这个检查覆盖已复现的有限模式；已有控件的试用问题仍可以聊，不保证模型永远不离题。

说「先停这轮编程」「停止生成」「别再写代码了」会停止实际 DSH 任务，等待退出后确认。停止编程保留作品和需求，聊天继续；「不要停止生成」、引用和假设中的停止指令不会触发取消。

说“先修正这张需求卡，不要编程”时会更新卡片并提议当前版本，不会误判为取消；同句的明确停止指令仍生效。实际语音曾复现取消误判，首次五次真实重放又发现一次回复已邀请确认但标记仍指向旧卡；修复后五次独立真实 DeepSeek 重放均更新到当前待确认版本。原失败证据保留，真人麦克风仍未验证。

DeepSeek 与 MiMo key 在 Windows 使用用户级 DPAPI，在 Mac 桌面包使用系统钥匙串保存，公开接口只返回配置状态。开发环境的数据位于 `.data/`；安装后的 Windows 数据位于 `%LOCALAPPDATA%\doda`，Mac 数据位于 `~/Library/Application Support/local.doda.desktop`。公开源码与发布包不包含开发者凭据、聊天记录、录音或本机作品。

重新安装：

```powershell
npm.cmd ci
npm.cmd run asr:setup
npx.cmd playwright install chromium
npm.cmd run build
npm.cmd start
```

`asr:setup` 从 sherpa-onnx 官方 GitHub release 准备约 163 MB 的 SenseVoiceSmall int8 资源，校验固定 SHA-256。语音识别优先在本机 CPU 执行。模型尚未准备时才尝试 MiMo ASR；当前账号实测 MiMo ASR 返回 402，本机识别已通过真实 WAV 验证。回复声音使用 MiMo 官方苏打男声和冰糖女声预设。

`package.json` 为 react-if-lite 指定使用项目的 React 版本，标准安装会保留完整 DSH peer 依赖。不要用 `--legacy-peer-deps`：它曾移除 DSH 启动所需的间接依赖。2026-10-10 本次界面已在内置浏览器实际制作、试玩、切换机型并验证截图识别。桌面入口为 `start-doda.cmd`，EXE 与 `server/`、`dist/`、`node_modules/` 一起使用，依赖本机 Node.js 和 WebView2，目前不是自包含安装包。EXE 已编译；原生窗口和退出清理尚未验收。

## 创作流程

1. 与 doda 聊具体功能、操作和规则，确定后再自然地聊视觉感觉。用户已经给出风格或让 doda 决定时，不重复追问，不要求选择设计系统。
2. doda 在对话里展示本轮需求摘要，细节可以展开，通过聊天修正。首版最多三项功能；说“先聊、还不整理”时继续讨论并清掉旧的待确认状态。说“就按这版开始做吧”或点击“开始制作”即按当前待确认版本制作；一般肯定句仍结合上下文判断。整理失败或版本已变时不能自动执行，未采纳的建议不进入需求卡，确认时不重新改写需求。
3. 固定需求、内部设计包和 SHA-256 快照，另起 DSH 上下文和进程。启动时固定模型和凭据，本轮不受后来修改设置影响。当前项目同时只允许一个实现任务；完成和取消均等待本轮收尾与状态保存。
4. 生成期间继续讨论，明确暂缓的想法进入灵感清单，当前预览仍能继续试玩。编程使用 low 思考强度，每次请求输出上限为 16384；遇到原生输出截断，在同一会话中续写最多一次，此次数与编译修正共享。候选工程有编译错误时，把文件、位置和诊断交回同一个 DSH 会话，最多修正两次，期间仍可聊天或停止任务。原有作品保留到候选工程检查通过。
5. 交付消息提供“看看这版”。语音模式在句间播报完成提醒，再恢复聆听。
   主对话读取最近成功版本的冻结需求、可见摘要和有界源码，不读取尚未完成的候选代码或原生会话内部记录。即使下一轮草稿变了，回答当前作品细节仍依据已交付内容；资料截断或缺失时会明说。
6. 预览交互、查看文件差异、右键圈选区域，继续聊下一版。预览中的本机数据按项目保存，刷新后恢复。
7. 下载 WXML/WXSS/JS/JSON 工程，导入微信开发者工具。设置 AppID、开发者工具路径和上传密钥后可调用预览码/上传接口，正式审核发布仍在微信公众平台完成。

## 已验证

- 抽签：逐字输入、回车添加、最多五件、拒绝第六件、随机结果、删除结果事项、刷新恢复。
- 喝水打卡：点击杯子计数、八杯上限、撤销、刷新恢复当天进度。
- 自行发现跨午夜计数沿用昨天数据的 bug，通过 doda 聊天交给 DSH 完成第二轮修复；受控日期复测中，新一天点击计数为 1，撤销不继承昨天记录。
- 录音样本三轮：真实本机 ASR → DeepSeek 主对话和需求记录 → MiMo 回复 WAV；第三轮“就按这个做”触发独立 DSH。生成期间另一次真实对话成功，下一版“每周喝水趋势”进入灵感，执行快照保持不变。该验证替换了麦克风与播放端口，不能当作真人麦克风全链路验收。
- 浏览器已取得真实麦克风并进入“我在听”，但尚未采集真人连续两轮语音。自动往返、重复回调、停止、打断、播报失败、完成提醒和录音分句有契约测试。
- 猫猫投喂记录生成了两页与共享 CommonJS 模块。自行体验后修复预览器的模块加载、页面生命周期、页面栈、嵌套 setData 和存储副本，已验证记录三次、倒序历史、返回、刷新保留当前页面与记录。时间精确到秒的第二轮由独立 DSH 实现。
- 语音保持连接时启动真实 DSH 任务，交付后浏览器自动收到 MiMo 200 WAV，进入播报状态，播放结束后自动恢复聆听。此项完成提醒使用真实浏览器、麦克风连接和播放链路；仍不等同于真人连续两轮语音验收。
- 反应小游戏：通过页面里的聊天生成、确认和交付；试玩发现 200 毫秒内的提前点击被忽略，通过 doda 再交给 DSH 修复。浏览器复测快速双击判抢跑且之后不变绿、正常成绩、重试、最佳成绩刷新恢复及较慢成绩不覆盖最佳纪录。修复期间的真实聊天记下“平均成绩”灵感，当前快照与代码没有加入它。
- 编译自动修正：隔离候选工程中明确注入一个 WXML 表达式错误，真实 DeepSeek 在同一个原生 DSH 会话里读取官方编译诊断并修正，最终检查通过；原作品未改动。这是受控错误注入验证，不能描述成模型自然生成的编译错误。
- 生成时继续试玩：浏览器实际复现新任务启动把旧版游戏从变绿重置为未开始，修复后启动真实 DSH 任务不再刷新预览，交付成功后才载入新版。任务失败或取消也不会触发预览刷新。
- 交付恢复：先复制出完整待安装目录，再切换当前目录；安装失败会还原旧版，复制后取消也保留旧版。重启时恢复未结束任务的旧版文件，残缺的新目录移到执行记录内保留，聊天只报告一次中断。文件系统故障、退出时磁盘状态和恢复路径均由隔离回归验证，不等同于断电或微信真机测试。
- 聊天停止：在实际原生 DSH 会话运行时调用真实聊天接口，确认取消后再返回；原版小程序文件 SHA-256、需求卡及版本保持一致，随后真实 DeepSeek 对话没有开启新任务。此项使用文字输入真实聊天接口，不能描述成真人语音取消验收。
- 翻牌找伙伴：浏览器实际翻开、记住并配齐六对小动物，11 次配对后显示完成；同一张牌双击不加次数，不匹配等待中第三张牌不翻开。实际生成的 JS 在受控时间边界验证 600 毫秒回盖、重开、过期回调、卸载清理及已配对进度，共八项通过。
- 试玩发现窄预览把十二张牌错排成两列，修正预览器按窗口宽度换算 rpx；WXSS 和动态内联样式共用此换算。实际浏览器已恢复三列，生成的小程序代码不受影响。换算依据腾讯官方[视图层文档](https://intl.cloud.tencent.com/ind/document/product/1219/61744)。
- 等待接话：实际浏览器麦克风保持空闲时，两次真实原生编程任务中均收到 DeepSeek 生成的问句、MiMo 200 WAV，任务结束后又收到结果提醒并恢复聆听。包含一次失败和一次成功任务，问句接受时间均处于任务运行区间。未采集真人回答或独立验证物理扬声器可听性。
- 猫猫奇遇：十二场景、四个结局、两页足迹与重开。发现首轮需求记录自行增加了用户未要求的“返回上一场景”，随后收紧记录规则，并通过实际页面聊天明确移除，确认后由独立 DSH 交付修正版本。故事正文保留；最新版本的四个结局分别从新一局实际走到，验证足迹只含实际选择、返回保留场景、两个页面确认重开及取消保留进度。实际生成的 JS 另通过八项隔离行为检查，包括没有撤销按钮、处理方法或历史栈，所有场景可达，所有向前选择都能结束，以及不存档。
- 输出截断：首次真实故事任务达到 8192 输出 token 上限且没有可见回复或代码交付。修改编程配置与有界续写后，用相同需求快照重试；原生会话在 16384 上限截断后续写，随后实际写入 12 次并交付。这是同一份持久原生 DSH 会话中的真实续写，证据不包含推理内容。
- 故事试玩实际复现预览缺少 `pageScrollTo` 与 `showModal`，已补充数字位置滚动及基本确认弹窗。浏览器验证回到顶部、真实等待取消或确认、不重复回调；修复后的试玩没有新增控制台错误。接口形状参考微信团队[官方 API 类型](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)，预览只覆盖已实现的子集。

## 验证边界

预览使用微信团队官方 glass-easel 1.2.1 的 WXML/WXSS 编译器、组件运行时和小程序适配器直接运行原生页面与自定义组件。基本输入、按钮、组件事件、插槽和页面生命周期走官方运行时；官方 Web 包未提供完整微信内置控件和平台 API，复杂表单、canvas 等能力使用现有兼容渲染。制作中的文件形成完整可运行版本后自动更新，写入中断时保留上一份可用画面。它仍不能替代完整开发者工具或微信真机。

工程检查覆盖文件结构、JSON、JS 语法及官方 WXML/WXSS 编译；编译错误和缺失依赖阻止交付，警告单独报告。旧 miniprogram-ci 2.1.31 的 WCC/WCSC 在当前 Windows Node 环境缺少 `node.dll`，仍未加载；新增检查不依赖该原生模块。当前未配置微信 AppID、上传密钥或开发者工具，开发者工具运行、真机、预览码与上传均待验证。

主对话目前按句往返，TTS 按回复生成 WAV，未实现全双工自动抢话、流式 TTS 或完整微信 API 模拟。预览滚动只支持数字 scrollTop，非零时长由浏览器平滑滚动近似；弹窗只支持标题、内容、确认与取消，未覆盖可编辑弹窗。DSH 仅启用项目内 `doda_list/read/write/use_component` 工具，关闭常规 shell，检查路径和符号链接；这是工具边界，不是操作系统容器沙箱。
